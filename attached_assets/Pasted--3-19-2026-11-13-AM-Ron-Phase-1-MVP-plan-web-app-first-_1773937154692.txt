Goal

A simple CBO web app where:

1. Members create a free profile + sign in
2. They can view a calendar/list of upcoming CBO events
3. They can check in when they arrive at an event
4. Admins (Patrick/Lue) can add/edit events from an admin dashboard

Core roles

• Member (default): sign up, manage profile, view events, check in
• Admin (Patrick/Lue): everything a member can do + create/edit/publish events, view attendance/check-ins

Phase 1 features (must-have)

A) Auth + profiles

• Email/password sign up + sign in (simple)
• Minimal profile:
  • name (required)
  • email (required)
  • business name (optional)
  • industry (optional)
  • phone (optional)
• “My Profile” page to edit these fields

B) Events (public-to-members)

• Events index with two views:
  • Calendar view (month/week toggle optional; can start with month)
  • List view (upcoming, sorted by date)
• Event detail page with:
  • title
  • start/end datetime
  • location (name + address or “Zoom” + link)
  • description
  • organizer (optional)
  • capacity (optional for later; we can omit in MVP)

C) Check-in (the main value)

• From event detail page: Check In button
• Check-in creates a record: (user_id, event_id, timestamp)
• Show “Checked in” state + timestamp once done
• Basic guardrails:
  • prevent duplicate check-ins
  • allow admin to “undo” a check-in if needed

D) Admin dashboard (Patrick/Lue)

• Admin-only area:
  • create/edit/delete events
  • publish/unpublish (optional; or just “active” boolean)
  • view attendee check-in list per event (export CSV optional later)

Phase 1 UX / navigation (simple)

Left sidebar tabs:

• Dashboard (optional “next event” summary)
• Calendar
• Events (list)
• My Profile
• Admin (only visible to admins)

Data model (minimal)

• users: id, email, password_hash, name, business_name, industry, phone, role
• events: id, title, description, start_at, end_at, location_name, location_address, virtual_url, status
• checkins: id, user_id, event_id, checked_in_at (unique constraint user_id+event_id)

“Not in Phase 1” (explicitly deferred)

• Email notifications/reminders
• Ticketing/payments
• RSVP / waitlists
• Mobile app packaging
• Member directory / networking features
• Facebook scraping + auto-sync (manual event entry first)

Acceptance criteria (what “done” means)

• Admin can create an event in <2 minutes
• Member can sign up, view calendar, open event, check in in <30 seconds on a phone browser
• Admin can see live check-in counts per event + list of who checked in
• No emails, no payments, no extra complexity
